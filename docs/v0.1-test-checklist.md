# v0.1 Self-contained Survivor Core 测试清单

测试时禁用 MultiSlots、CreateSurvivorBot、Left4DHooks 提供的 takeover 功能及旧 dead-bot fix。

## Engine

- [ ] 正常加载时日志包含 gamedata initialized。
- [ ] 移走 gamedata 后插件明确 fail，恢复文件后可加载。
- [ ] late load 后在线玩家状态识别正常。

## 4 人

- [ ] Active Survivor 执行 `!afk` 后变为 Engine Idle，关联 Bot userid 正确。
- [ ] `!join`优先接回自己的 Bot。
- [ ] 连续执行 `!afk` → 等待确认 Idle → `!join` → 等待恢复 Active Survivor，至少循环 5 次；每次都不得出现错误的 `IdleFailed` / `TakeoverFailed`。
- [ ] 被五类控制状态影响时 `!afk`被拒绝。
- [ ] 倒地和挂边允许 Idle，死亡拒绝。
- [ ] Free Spectator 可接管已有空闲 Bot；没有 Bot 时可以创建并接管。
- [ ] `!spec`与`!spectate`等价，且与`!afk`的 Engine Idle 语义明确分离。
- [ ] Active Survivor 执行`!spec`后成为 team 1 Free Spectator，不保留 Idle Bot 归属。
- [ ] Engine Idle 执行`!spec`后，原 Bot 仍是 Survivor Bot，且`m_humanSpectatorUserID` 已清零。
- [ ] 从 Engine Idle 进入`!spec`后执行`!join`，走普通空闲 Bot 的 bind + takeover，不走 return-from-idle。
- [ ] Free Spectator 执行`!join`时优先接管可用 Bot，无可用 Bot 时创建 Bot 并接管。
- [ ] `!zs`只对活着的真人 Survivor 生效。

## 5/8/12/16 人

- [ ] 始终保持官方 `survivor_limit 4`，不要把它改成 Players 容量。
- [ ] 配置足够 MaxClients，设置 `sm_l4dp_survivor_limit 5`；1 真人 + 3 Bot 时执行 `sm_l4dp_addbot 1`，得到 1 真人 + 4 Bot = 5 Survivors。
- [ ] 分别设置 `sm_l4dp_survivor_limit 8`、`12`、`16`，使用同一 `sm_l4dp_addbot [count]` 补足到对应总数。
- [ ] 每个新 Bot 均存活、可以正常 AI 移动/战斗，创建过程和后续游戏不崩溃。
- [ ] 非 root 管理员和普通玩家不能执行 `sm_l4dp_addbot`；命令不出现在玩家菜单。
- [ ] `sm_l4dp_addbot` 不能突破当前 `sm_l4dp_survivor_limit`，无临时客户端槽时 error log 明确记录原因。
- [ ] 每名新玩家可创建 Survivor 并加入。
- [ ] 两名 spectator 同时 `!join`不会接管同一 Bot。
- [ ] 到业务上限、客户端槽上限时给出不同失败提示。
- [ ] `!afk` / `!join` / `!spec` 在 5+ Bot 环境中不回归。

## Dead bot

- [ ] 5+ 环境中 Idle 关联 Bot 死亡时真人不会掉为 Free Spectator。
- [ ] 后续 `!join`和下一章节仍能恢复正常状态。
